# re-arch

[English](README.md) | [Français](README.fr.md) | [Español](README.es.md) | [Deutsch](README.de.md) | [Português](README.pt-BR.md) | [Italiano](README.it.md) | [简体中文](README.zh-CN.md) | **日本語** · **[ウェブサイト](https://gregorybabonaux.github.io/re-arch/?lang=ja)**

![re-arch レポート：サマリーとドメインマップ](docs/images/banner.png)

既存アプリケーションのアーキテクチャを監査し、理解するコストと構築するコストで規模を見積もったターゲットアーキテクチャを提案し、リファクタリング (refactoring) を計画し、経営層向けの説明資料を作り、選んだターゲットに沿って AI コーディングエージェントと CI を整え、チーム自身のコードをもとにした研修教材を作成する、エージェントスキル (agent skill) のスイートです。あらゆるコードベースを対象に設計していますが、特にバイブコーディング (vibe coding) で作られたコードや AI が生成したコードベースを想定しています。

対応エコシステム: JavaScript / TypeScript、PHP、.NET (C#)、Java / Kotlin、C / C++、Go、Rust。

## 得られるもの

リポジトリで `re-arch-audit` を実行すると、`.re-arch/` に次のものが出力されます。

- アプリケーションの**ドメインマップ** (業務領域、依存関係、C4 のコンテキストビューとしての外部システム、境界があいまいなゾーン、ドメインごとの確信度)。フォルダ構成に意味がない場合でも作成できます。
- **診断**: すべての指摘がファイルと行を引用し、チームとビジネスへの影響、修正の規模を示します。あわせて、維持すべき強み、**悪く見えるが問題ないもの**、メンテナーへの未解決の質問も含みます。
- **2 から 4 つのターゲット案** (「構造はそのままで的を絞ったリファクタリング」から、レイヤード、バーティカルスライス、モジュラーモノリス、クリーン / ヘキサゴナル、そしてコードが正当化する場合は CQRS やイベントソーシングまで)。それぞれ**理解コスト**と**実装規模** (S, M, L, XL) で見積もり、ビジネスの**品質シナリオ**に照らして評価します。ドメインごとに異なる案になることもあり、検討して却下したスタイルも示します。
- 明確な基準付きの T シャツサイズによる**段階的リファクタリング計画**: まず特性テスト (characterisation tests) によるセーフティネット、`verify` コマンド付きのステップ、出口ゲート、ロールバック、停止ポイント、そしてクリティカルおよび高の指摘をすべてカバーします。
- **経営層向けの提案資料**: リスク、何もしない選択肢を含む案、算出根拠付きのキャパシティ幅で示す投資額、マイルストーン、指標、求める意思決定。
- **ガードレール**: ルートおよびドメインごとの AGENTS.md、新しいコードをどこに置くかをエージェントに伝えるプロジェクトスキル、エージェント自身のターン内でアーキテクチャチェックを実行する**エージェントフック (hook)**、**凍結したベースライン**とともに導入する CI 用のフィットネス関数 (fitness functions) (エコシステムごとのネイティブツールと言語非依存のチェッカー)、ADR (MADR 4)、レビューチェックリスト。
- **アカデミー**: 計画に沿った学習パス、リポジトリの実ファイルに基づくモジュール (ビフォー / アフター、カタ、レビュー用の質問)、厳選した参考資料。
- すべてをまとめた**レスポンシブな HTML レポート**: データコントラクトに対して検証し、スマートフォン幅での表示も確認済みで、PDF として印刷できます。リポジトリのドキュメント用に Mermaid 図も出力します。
- アーキテクチャの知識 (システム、ドメイン、外部システム、意思決定、ルール、ロードマップ、履歴) をまとめた **[Open Knowledge Format](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md) (OKF v0.2) バンドル**: `docs/architecture/okf/` にコミットし、人、コーディングエージェント、ナレッジカタログが利用できます。トラストフィールドがチームの検証済み内容を示し、機密情報は含めません。
- **再監査**: 解決されたもの、新たに見つかったもの、メトリクスの変化を示します。

## スキル

| スキル | 役割 | スクリプト |
|---|---|---|
| `re-arch-audit` | オーケストレーター、ドメイン検証と案の選択のためのチェックポイント、再監査モード | `diff_rearch.py` |
| `re-arch-scan` | 依存グラフ (可能な場合はコンパイラ水準)、DI の配線、ビルド単位、結合度、循環、ホットスポット、同時変更 (co-change)、知識の分布、重複、データモデル、ルート、外部システム、依存関係の衛生、シークレット | `scan.py`, `precise.py`, `di.py`, `insights.py`, `ts_resolve.js`, `php_refs.php` |
| `re-arch-domains` | import + DI + 同時変更 + データモデル + ルートから導く業務ドメイン | `cluster.py` (Louvain) |
| `re-arch-diagnose` | 根拠、重大度、修正規模付きの指摘、「指摘しない」リスト付きのスメルカタログ | |
| `re-arch-options` | ターゲットアーキテクチャ、2 軸の規模見積もり、品質シナリオ、根拠整理表、スタイルカタログ、エコシステムごとのイディオム | |
| `re-arch-plan` | 段階的な計画、検証可能なステップ、出口ゲート、段階的移行のテクニック | `plan_to_md.py` |
| `re-arch-pitch` | 経営層向けの説明資料 | `pitch_to_md.py` |
| `re-arch-guardrails` | エージェント用ルール、プロジェクトスキル、エージェントフック、ベースライン付きフィットネス関数、ADR | `check_architecture.py` (+ 同梱のスキャナー) |
| `re-arch-academy` | チーム自身のコードを使った研修教材 | |
| `re-arch-report` | HTML レポート、コントラクト検証、表示チェック、Mermaid と OKF のエクスポート | `render.py`, `validate.py`, `check_render.py`, `to_okf.py` |

各スキルは単独でも動作します。スキル間のデータ受け渡しは `.re-arch/` 内の JSON ファイルで行います。コントラクトは `skills/re-arch-audit/references/contract.md` に定義され、`validate.py` によって強制されます。

## 依存グラフの精度はどの程度ですか?

スキャンは、利用可能な場合はその言語自身のツールを使い、その旨を「Graph sources」セクションに明記します。利用できない場合は正規表現による解決にフォールバックします。

| エコシステム | 精密なソース | 必要なもの |
|---|---|---|
| C/C++ | `compile_commands.json` (実際の `-I`/`-D`) + プリプロセッサの include ツリー | コンパイルデータベース (CMake `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`、`bear`)、コンパイラ |
| Go | `go list` (ビルドタグ、正確なモジュールパス) | Go ツールチェーン |
| Rust | `cargo metadata` (クレートグラフ、クレートをまたぐ `use`) | Cargo |
| Java/Kotlin | コンパイル済みクラスに対する `jdeps` | JDK とビルド済みのプロジェクト |
| .NET | `.csproj` の ProjectReference グラフ (ありえないエッジを除外) | 不要 |
| JS/TS | TypeScript 自身のモジュールリゾルバー | リポジトリ内の `typescript`、または `--fetch-tools` |
| PHP | 完全な名前解決を行う PHP トークナイザー | `php` バイナリ |

依存性注入 (DI) は別途解決され (.NET の登録、NestJS/Angular のプロバイダー、Laravel のバインディングとファサード、Symfony のサービス、Spring の `@Bean`、Google Wire、単一実装)、import とは区別した**ランタイムエッジ**になります。レイヤリングのルールは import を使い、結合度とドメインは両方を使います。リフレクションや規約ベースのスキャンは引き続き検出できず、どのレポートにもその旨が記載されます。

## 設計方針

- **意見より根拠を先に**: まず決定論的なスキャンを実行します。指摘はコードを指し示し、診断では指摘しないと判断したものも示します。
- **デフォルトのアーキテクチャはありません**: 軽量な案が常に選択肢に含まれ、すべての案はコード内のシグナルで正当化され、品質シナリオに照らして評価されなければなりません。クリーン、ヘキサゴナル、オニオンは選択肢のひとつであり、品質の段階ではありません。「現在のアーキテクチャを維持する」も正当な結論です。
- **コストを見える化します**: 実装規模と並べて理解コストを示します。
- **日数ではなくサイズで**: 明確な基準付きの T シャツサイズを使います。XL は「分割せよ」を意味します。経営層には算出根拠付きのキャパシティ幅を提示します。
- **2 種類の読み手**: 技術チームには根拠と検証可能なステップを、経営層にはリスクと意思決定事項を提示します。
- **定着するリファクタリング**: 凍結ベースラインのフィットネス関数、エージェントフック、ドメインごとのエージェント用ルール、リポジトリを使った研修、再監査で支えます。
- **人は指摘の対象ではありません**: 知識の集中は仮名 (`A1`, `A2`) で報告し、対応表はローカルにのみ保持します。

## 動作要件

- Python 3.8+ (コア部分は標準ライブラリのみ)。
- 任意 (精密モード用): 上記の各言語ツールチェーン、TypeScript リゾルバー用の Node。
- 任意: レポートの表示確認用に Playwright + Chromium (`pip install playwright && python -m playwright install chromium`)。
- 任意: 監査対象リポジトリの git 履歴 (同時変更、ホットスポット、知識の分析に使用します。シャロークローンは避けてください)。

## インストール

**Claude Code**（1 ステップ、Claude Code 2.1.275 以降）：

```
/plugin install re-arch --marketplace GregoryBabonaux/re-arch
```

それより前のバージョンでは、`/plugin marketplace add GregoryBabonaux/re-arch` を実行してから `/plugin install re-arch@re-arch` を実行します。

**その他のエージェント**（Codex、Cursor、Gemini、Copilot など）：

```
npx skills add GregoryBabonaux/re-arch
```

`-g` を付けると、すべてのプロジェクトにインストールされます。

あとは監査したいプロジェクトで「このリポジトリのアーキテクチャを監査して」と頼むだけです。

更新：`claude plugin update re-arch@re-arch`（Claude Code）または `npx skills update`。

## 開発

- `python3 tests/test_suite.py -v`: エコシステムごとのフィクスチャリポジトリに対する 34 個のテストです。各フィクスチャには正規表現レイヤーが誤る罠 (マクロで計算される include、include ディレクトリの衝突、クレートをまたぐ `use`、インラインの修飾名、プロジェクト間の名前空間の衝突、ビルドタグ、同一名前空間内の PHP 参照) が仕込まれており、精密レイヤーと DI 抽出がそれらを正しく扱えることを確認します。さらに、チェッカーのベースラインとフック、コントラクト検証、スマートフォン幅での表示、再監査の差分、OKF エクスポート (仕様準拠、トラストフィールド、ログ履歴、機密情報が含まれないこと) もテストします。ツールチェーンに依存するテストは、そのツールチェーンがない場合スキップされます。
- スキャナーを変更した後は `python3 tools/sync.py` を実行してください (guardrails スキルがコピーを同梱しているため)。CI では `--check` を使います。
- `evals/`: エンドツーエンドの評価 (`evals.json`、`evals/grade.py` で採点) です。正解が「ヘキサゴナルに移行しない」となる健全なリポジトリも含みます。スキルの説明文に対するトリガークエリ (`triggers.json`) もあります。
- `.github/workflows/tests.yml` がこれらすべてを実行します。
